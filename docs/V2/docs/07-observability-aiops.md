# Observability & AIOps

## 1. 운영 구조

```text
Spring Boot
 ↓
OpenTelemetry
 ↓
Collector
 ↓
┌──────────────────┬──────────────────┐
│ 시스템 관측 신호   │ 진단 품질 신호   │
└──────────────────┴──────────────────┘
 ↓
AIOps Agent
 ↓
근거 연관 분석
 ↓
원인 후보 / 수정 제안
 ↓
개발자 판단
```

## 2. 시스템 관측 신호

- 로그
- 메트릭
- 트레이스
- HTTP Error
- 응답시간
- DB 상태
- 외부 API Timeout

## 3. 진단 품질 신호

- UNKNOWN 비율
- PARTIAL 비율
- 외부 데이터 실패율
- 데이터 신선도 문제
- Rule 결과 분포
- 지역 Rule 실패
- 진단 실패율

## 4. AIOps Agent 권한

### 가능

- 마스킹된 로그 조회
- Metric 조회
- Trace 조회
- 배포 정보 조회
- Commit 정보 조회
- 근거 연관 분석
- 원인 후보 생성
- 수정안 제안

### 불가능

- 운영 환경 직접 수정
- 승인 없는 코드 변경
- 자동 배포
- 사용자 정확한 위치정보 조회
- 사용자 전체 여행 일정 원본 조회

최종 판단은 개발자가 한다.

## 5. 운영 Loop

```text
운영 신호 수집
 ↓
AIOps Agent 분석
 ↓
원인 후보 / 수정 제안
 ↓
개발자 판단
 ├─ 수정 불필요 → 계속 관측
 └─ 수정 필요
      ↓
    개발자 승인
      ↓
    개발 Workflow
      ↓
    재배포
      ↓
    운영 지표 재확인
```

## 6. 개인정보 / 로그 정책

### 사용자 정확한 위치

- 원본 로그 저장 최소화
- 필요 시 마스킹

### 전체 여행 일정

- 필요 이상 로그에 기록하지 않음

### 사용자 식별정보

- 내부 익명 식별자 사용

### 좌표

- 운영 분석 목적에 따라 축약 / 비식별화

### AIOps Agent

- 마스킹된 관측 데이터 중심으로 접근
