## 6. Codex A 주요 판단

### 구현 방식

- 상위 React 상태에 여행 조건과 장소 ID별 편집값 보관. 순서 이동·장소 추가 왕복에 활동/최종 체류시간 유지. 새로고침 시 초기화 사실 표시. 새 상태 라이브러리·라우터·의존성 없음.
- 빈 날짜·시작/종료·머무를 시간에서 입력 시작. 활동을 선택하면 확인된 합계로 머무를 시간 자동 입력. 출발지는 기존 앱의 부산역 좌표를 재사용하거나 검색 결과를 선택.
- 일반 활동시간 조회 API가 없음을 확인하여 기존 `ActivityType`의 코드/일반 활동시간을 조회하는 작은 내부 API 추가. 새 임계값·활동시간 정책 생성 없음.
- `GET /api/planner/activity-policy` 배열: `code`, `label`, `durationSeconds`, `customDurationRequired`. 일반 활동은 기존 분을 초로 변환, `rest`·`other`는 null/true. V1 REST 20분·OTHER 30분 진단 로직은 변경하지 않음. 새 V2 입력에서는 사용자 지정 시간을 사용하며 향후 V2 서버가 이를 검증·사용해야 함.
- 서버 활동 조회가 실패하거나 잘못되면 활동시간을 임의 대체하지 않음. 15초 타임아웃·재시도·언마운트 취소 제공. 선택값은 유지하되 정책 없이 입력 확인 통과 불가.
- 활동은 체크박스로 중복 방지. 휴식·기타 활동은 각각 양의 정수 분 직접 입력. 휴식 선택 시 빈 시간 입력란이 나타나며 20분을 자동 적용하지 않음. 두 활동의 입력값은 별도 상태로 유지하고 선택 해제 중에는 합계에서 제외. 다시 선택하면 해당 장소에 입력한 시간을 복원한다.
- 활동 선택·해제 및 휴식·기타 활동시간 수정 시 합계로 머무를 시간을 자동 입력한다. 카페 40+식사 60+쇼핑 50+사용자 휴식 20=170분. 활동과 독립된 추가 휴식/여유시간 필드나 중복 합산 없음.
- 사용자가 자동 입력값을 직접 수정할 수 있으나 이후 활동 변경 시 새 합계로 갱신함을 UI에 안내. 활동이 없거나 휴식·기타 활동시간이 미입력/잘못된 경우 자동 입력은 비움. 활동시간의 미확인을 0으로 대체하거나 마지막 유효 합계를 남기지 않음. 현재 서버 정책은 분 단위이며 정수 분으로 정확히 표현할 수 없는 합계를 임의 반올림하지 않음.
- 화면 왕복·순서 변경은 수동/자동 입력값을 유지. 서버 정책시간 변경만으로 기존 입력을 덮어쓰지 않으며 활동 코드·시간 스냅샷으로 변경 안내. 확인 체크박스나 확인 플래그 검증 없음.
- 장소별 기본 권장시간 근거가 없어 권장값은 임의 생성하지 않음. 자동 입력은 선택 활동 기준의 계획임을 표시. ‘머무를 시간’은 사용자 수정이 가능한 최종 `plannedStaySeconds`이며 활동·휴식을 포함한다. 활동시간보다 짧더라도 형식상 유효한 입력을 차단하지 않으며 부족 여부의 진단은 후속 서버 Rule 책임.
- ‘방문시간 지정’ 기본값은 꺼짐. 하단 보조 옵션으로 배치하고 켰을 때 방문 시각 필드를 노출. 켜고 비우거나 여행 시간 범위 밖이면 오류. 끌 때 기존 시각을 지우고 요청에서 `plannedVisitTime` 제외. 화면 왕복·순서 변경에 옵션과 입력 시각 유지.
- `buildDiagnosisInput`은 향후 요청 변환용 순수 함수이며 현재 서버로 전송하지 않음. 최종 100분은 6000초만 사용하고 활동시간은 별도 필드. 기타 75분은 4500초 유지. 선택 순서와 공통 placeId 유지.
- ‘입력 확인’은 날짜/시간/양수/중복/지정 방문시간의 입력·범위만 검사. 이동·대기·도착·잔여시간 및 POSSIBLE/SAFE/VERIFIED 등 판정 생성 없음.
- 출발지 검색은 기존 관광지 검색 API의 첫 페이지 최대 20곳. 일반 주소 검색이 아니며 한계를 명시. 빈 결과/오류를 구분하고 기존 선택 출발지 유지. 최신 요청 우선·취소·15초 타임아웃 제공.

### 기존 구조와의 관계 / 구현 전 검증

- Rule·Registry·DiagnosisEngine·지역 Scope·판정 집계는 변경하지 않음. 기존 V1 진단 API도 유지.
- 일반 활동시간의 원본은 서버이며 웹에 고정 시간표를 복사하지 않음. 외부 API 직접 호출·SDK 의존·외부 원본 저장 없음.
- 활동 조회는 내부 정적 정책 조회로 Port/Adapter 대상인 외부 데이터 호출이 아님.
- INV-001/004/005/008/009 확인: 미확인 정보 안내, 필수 입력 검증, 진단 결과 미생성, 최종 체류시간 중복 합산 없음. INV-002/003에 해당하는 Rule 변경 없음. INV-006 원본 저장 없음.
- 작업 시작 전 존재하던 모바일 condition/diagnose/store 및 architecture 문서 수정은 그대로 보존.

### 구현 중 발견한 문제

- 초기 테스트에서 활동 레이블의 인접 텍스트 공백 누락 및 테스트 레이블 오타 발견. 공백과 테스트를 수정한 뒤 전체 재실행.
- 시각 확인에서 모바일 10개 활동 1열이 길어짐을 확인. 380~760px에서 활동명/시간을 묶은 2열, 좁은 화면은 1열로 조정.
- 초기 구현의 체류 확인 체크박스가 입력 부담을 준다는 개발자 피드백에 따라 확인 플래그·검증을 제거. 이후 개발자의 활동 합계 자동 입력 요구에 따라 활동 편집 시 합계로 갱신하고, 외부 정책 변경에만 기존 입력 유지·안내를 적용함.

## 7. 구현 전 개발자 판단 요청

### Agent가 요청한 판단

- Agent의 임의 정책 결정 없음. 서버 조회 API 부재와 기존 일반 활동시간 재사용·사용자 지정 시간·권장시간 근거 부재 처리를 보고함. 휴식 20분 고정→직접 입력은 개발자의 명시적 후속 지시를 반영함.
- UI 세부 배치는 개발자가 위임함. 활동시간 부족 판정 등 서버 책임은 웹으로 이동하지 않음.

### 개발자 결정

- 장소별 활동 선택 포함.
