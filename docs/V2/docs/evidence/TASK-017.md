## 11. Review 이후 수정사항

2026-11-22 개발자가 전달한 재리뷰는 기존 P2 세 건의 반영을 확인하고 **CHANGES_REQUIRED**를 제시했다. 추가 P2 두 건은 문장 오류 후에도 계속하는 SQL 세션에서 초기 연결만 커밋될 가능성과, 해운대 실시간 검색 첫 항목의 정상 미수집을 테스트가 실패 처리하는 문제다. 리뷰어는 기존 실행 기록을 확인했고 테스트·DB SQL을 재실행하지 않았다.

초기 연결 SQL의 두 INSERT와 COMMIT을 한 MySQL 프로시저 호출에 두고, 예외 처리기가 전체 롤백·임시 테이블 정리·잠금 해제 후 오류를 다시 전달하도록 했다. 전용 세션에서 수동 실행하며 실행 계정에는 프로시저 생성·실행·삭제 권한이 필요하다. 일반 검색 실연동 테스트는 실제 상세 응답별 안내 또는 표시값을 검증한 뒤 장소 추가와 일정 편집을 확인한다. F1963은 양쪽 출처의 실제 값과 시각을 계속 요구한다.

개발자가 수정 방향을 확인하고 진행을 지시했다. Repository에서 연결 근거를 조건으로 출처별 저장 문구와 상태 JSON을 읽고, Service에서 항목별 출처와 표시 상태를 구성하며 Controller는 HTTP 요청을 위임한다.

상세 응답은 `NOT_COLLECTED`(저장 행 없음), `EMPTY`(저장됐으나 표시할 값 없음), `AVAILABLE`을 구분한다. 저장소나 HTTP 오류는 웹 조회 실패로 표시한다. 필드의 `state`와 `checkedAt`은 해당 출처의 필드별 수집 상태·시각이다. 수집 시각은 한국시간으로 표시하고 운영 문구 차이는 `differs`로 양쪽에 표시한다. 표현 차이가 실제 영업 조건의 모순인지 판정하지 않는다.

실연동 테스트는 상세 창을 열기 전에 해당 ID의 요청을 기다리고 HTTP 200, 사용 가능한 비어 있지 않은 응답, 항목별 실제 문구·출처·수집 시각·차이 표시를 대조한다. F1963은 두 출처 모두를 요구한다. 미수집·표시값 없음·조회 실패는 별도 화면 테스트로 검증한다.
