# BusanFit V2 Project Overview

## 1. 프로젝트 정의

BusanFit V2는 사용자가 입력한 여행 일정을 단순 저장하거나 추천하는 서비스가 아니라, 일정이 실제로 수행 가능한지 여러 규칙과 외부 데이터를 이용해 진단하는 서비스다.

초기 검증 지역은 부산이다. 다만 서비스 구조는 부산에 고정하지 않고 전국 공통 진단 엔진 위에 지역 특화 규칙을 추가하는 방식으로 확장한다.

## 2. 사용자 흐름

```text
사용자
 ↓
Expo 앱
 ↓
일정 추가
 ↓
장소 검색
 ↓
TourAPI / 지도 API 검색
 ↓
검색 결과에서 실제 장소 선택
 ↓
방문 시간 / 체류시간 설정
 ↓
선택한 순서대로 일정 구성
 ↓
진단 요청
 ↓
Spring Boot
 ↓
진단 결과 반환
```

## 3. 진단 대상

전국 공통 진단:

- 이동시간
- 체류시간
- 운영시간
- 일정 충돌
- 날씨 위험

지역 특화 진단:

- 해당 지역 공공데이터 기반 통제 / 위험
- 현재 초기 대상: 부산

## 4. 결과에서 반드시 보여줄 정보

- 일정 판정
- 검증 상태
- Rule별 결과
- 판단 근거
- 문제 원인
- 조정 방법

## 5. 초기 지역 지원 전략

### 부산

- 전국 공통 진단: 지원
- 부산 지역 특화 진단: 지원

### 서울 / 제주 / 강원 등 초기 타 지역

- 전국 공통 진단: 지원
- 지역 특화 진단: 초기에는 미지원 가능

지역 특화 진단 미지원 사실은 숨기지 않고 Coverage Metadata로 표현한다.

## 6. 저장 원칙

MySQL에 저장할 수 있는 핵심 데이터:

- 사용자
- 여행 일정
- 일정 장소
- 방문시간 / 체류시간
- 최종 진단 결과
- Rule 결과
- 내부 정책 / 설정

외부 API 원본 응답은 무분별하게 저장하지 않는다. 서비스에 필요한 최종 결과와 판단 근거 중심으로 저장한다.
